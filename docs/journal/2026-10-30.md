## Problems and fixes

- **Forgejo exited seconds after starting, with no message.** The old control
  script discarded Forgejo's output. Running it in the foreground showed a
  fatal error: the `forgejo` user's home was `/nonexistent`, so Forgejo could
  not write its SSH key file. Fix: `usermod -d /var/lib/forgejo forgejo`.
  Recorded in the setup notes, 3.2.
- **The new `forgejo-ctl` passed every sandbox test, then failed on the real
  machine.** Ubuntu caches the `sudo` password per terminal; the script ran
  `sudo` detached from the terminal, so it needed the password again and
  failed silently. The sandbox ran as `root`, where `sudo` never asks, so it
  could not reproduce this. Fix: run `sudo` in the foreground and detach the
  service inside it (`setsid --fork`).
  **Lesson:** a stand-in test environment only catches what it models; the
  real machine is the final test.
- **Sandbox tests did catch three other `forgejo-ctl` bugs** before delivery:
  `curl` reporting `000` twice (start would refuse whenever Forgejo was
  stopped); a possible hang from `sudo`'s `use_pty`; and `start` trusting any
  program answering on port 3000.
- **Runner registration failed** ("runner registration token not found").
  `forgejo-runner register` is deprecated; current runners take their
  connection (url, uuid, token) in `config.yml`. The chat's first
  instructions used the old method. Setup notes, 4.2.
- **`config.yml` did not exist** after the first attempt; rerunning the
  generate step produced it.
- **The runner binary had been committed** by accident; removed in a later
  commit (it remains in the history).
